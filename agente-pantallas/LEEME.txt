================================================================
  SHAKEAHOLIC — AGENTE DE PANTALLAS
================================================================

Mantiene cada television del local mostrando lo que Admin le
asigno. Si alguien cambia de entrada o apaga la tele, la
reengancha sola en el siguiente ciclo.

Corre en la misma PC que los otros agentes, como proceso
APARTE: si este se cae, las comandas y los tickets siguen
saliendo.

----------------------------------------------------------------
LO QUE PUEDE Y LO QUE NO
----------------------------------------------------------------

  PUEDE    empujar imagenes y videos por DLNA
  PUEDE    detectar que esta mostrando cada tele y reportarlo
  PUEDE    reengancharla si alguien le cambio la entrada

  NO PUEDE encender una tele apagada
  NO PUEDE abrirle el navegador a una URL

  Las dos ultimas necesitan el puerto 36669 de Hisense, que
  exige un certificado de cliente que vive dentro de la app
  RemoteNOW. No hay forma de hacerlo por red.

  Consecuencia: el contenido dinamico (pedidos listos) NO va
  por aqui. Eso se abre una vez en el navegador de la tele y
  se actualiza solo. Este agente es para menu y promos, que
  son imagenes o video.

----------------------------------------------------------------
INSTALACION
----------------------------------------------------------------

  1. Node.js 20 o superior.
  2. En Admin -> Pantallas (TV), boton "Generar llave del
     empujador". Se ve UNA SOLA VEZ: copiala en ese momento.
  3. Copia .env.example como .env y llena SUPABASE_ANON_KEY
     y PANTALLAS_TOKEN (la llave del paso 2).
  4. npm install
  5. npm run buscar     <- lista las teles con su IP y nombre
  6. npm start

  Si la llave es mala, el agente NO se queda reintentando: se
  detiene de golpe para que el servicio lo marque como caido y
  alguien revise el .env. Un bucle silencioso con una llave
  muerta es peor que una caida visible.

----------------------------------------------------------------
PRIMERO: SABER QUE TELES HAY
----------------------------------------------------------------

  npm run buscar

  Da la IP y el nombre exacto de cada una, que es lo que Admin
  necesita para asignarles contenido. Ejemplo real del local:

    192.168.1.73    Barra trasera
    192.168.1.76    Barra larga
    192.168.1.80    Caja shakeaholic

  Una tele en standby NO aparece: VIDAA apaga su servicio DLNA
  con la pantalla. Enciendela y vuelve a correrlo.

----------------------------------------------------------------
DE DONDE SALE QUE MUESTRA CADA UNA
----------------------------------------------------------------

  De `fn_pantallas_tv_agente`, firmada con la llave. Devuelve
  cada TV activa con sus `diapositivas` ya filtradas por fecha
  y ordenadas. El contrato completo esta en
  docs/pantallas-tv.md del repo.

  La rotacion la lleva el agente con el reloj de cada imagen
  (`segundos`), no el ciclo de consulta. Por eso una TV de 8
  segundos rota cada 8 aunque la asignacion se pida cada 45.

  Las TVs con contenido `pedidos` o `nada` vienen sin
  diapositivas: el agente NO las toca. Esas las pone el
  navegador de la propia TV.

  IMPORTANTE: las URLs tienen que ser alcanzables DESDE LA
  TELE. El que descarga la imagen es el televisor, no esta PC.

----------------------------------------------------------------
CUANDO GERENCIA TOCA "VOLVER A PONER SU CONTENIDO"
----------------------------------------------------------------

  La asignacion trae `reenganchar_desde`. Si es mas nuevo que
  el ultimo empuje, el agente repone el contenido en la
  siguiente vuelta, sin esperar a que se cumpla el tiempo de
  la diapositiva.

----------------------------------------------------------------
EL REPORTE
----------------------------------------------------------------

  `fn_pantallas_tv_reportar` recibe, por cada TV, que esta
  mostrando DE VERDAD — no lo que se le mando. Esa diferencia
  importa: una tele puede aceptar el contenido y aun asi estar
  en otra entrada.

  Cuatro estados posibles:

    mostrando      todo bien
    sin_respuesta  apagada, en standby o fuera de la red
    otra_entrada   alguien le cambio la entrada; se reengancho
    error          la TV rechazo el contenido

  Se reporta en cuanto algo cambia, y si nada cambia, cada
  REPORTE_SEGUNDOS. Admin pinta "sin reporte" a los 3 minutos.

  Sin RPC_REPORTE funciona igual, pero el estado solo sale por
  consola y Admin no se entera.

----------------------------------------------------------------
PROBARLO SIN LA FUNCION DE LA BASE
----------------------------------------------------------------

  Pon ASIGNACIONES_ARCHIVO apuntando a un JSON con la misma
  forma que devuelve la funcion (hay un
  ejemplo-asignaciones.json en esta carpeta). Manda sobre el
  RPC y permite probar el empuje real contra las teles sin
  tocar la base ni gastar una llave.

----------------------------------------------------------------
COMO SABER SI ESTA VIVO
----------------------------------------------------------------

  El agente deja un archivo `estado.json` en su propia carpeta
  cada vez que habla con el servidor:

    ok          true si la ultima consulta salio bien
    pantallas   cuantas TV le toca atender
    error       que fallo, si fallo
    en          cuando fue

  Si ese archivo tiene mas de un par de minutos, el agente no
  esta corriendo. Es lo primero que hay que mirar, y es lo que
  revisa el instalador antes de decir LISTO.

  El .env se lee de ESTA carpeta, no de la carpeta actual. Como
  servicio de Windows el directorio de trabajo puede ser otro, y
  antes el agente arrancaba sin configuracion y moria callado.

----------------------------------------------------------------
SI ALGO FALLA
----------------------------------------------------------------

  "ninguna tele respondio al descubrimiento"
      Las teles estan apagadas, o esta PC esta en otra red o
      en otra VLAN. El descubrimiento es por multicast y no
      cruza routers.

  "no esta en la red (apagada o en standby)"
      Normal si la tele esta apagada. Vuelve sola al encenderla.

  "NO acepto el contenido"
      La tele rechazo la URL. Casi siempre es que no la puede
      descargar: compruebalo abriendo esa misma URL desde otra
      maquina de la red.

  "La llave del empujador no sirve"
      Se genero otra llave en Admin y esta quedo invalidada,
      o se copio mal. Genera una nueva y actualiza el .env.

  No se ve que rote
      Pon VERBOSO=1 en el .env y reinicia: cada avance queda
      registrado con el nombre de la diapositiva.

  Una fila que se ignora con "falta id o ip"
      La TV esta dada de alta sin IP en Admin. Corre
      `npm run buscar` para saber cual tiene.
